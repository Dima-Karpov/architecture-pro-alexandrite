# Александрит — observability и кеширование

Проектная работа шестого спринта курса «Архитектор ПО» (Яндекс Практикум).

Кейс компании «Александрит»: ювелирные украшения на заказ (онлайн-магазин, CRM, MES). Растёт нагрузка через API, заказы «зависают», MES тормозит на дашборде. Нужны планирование, мониторинг, трейсинг, логирование и кеширование — без правок бизнес-логики в этом репозитории, только архитектурные решения.

Исходная C4-диаграмма: [`assets/project/jewerly_c4_model.drawio`](assets/project/jewerly_c4_model.drawio) (также png в той же папке).

## Как устроен репозиторий

Публичный репозиторий. Пять каталогов — по одному на задание. Сдача — **один PR** со всеми решениями. После отправки ссылки на ревью правки не вносим, пока не ответит ревьюер.

Рабочая ветка: `work/sprint-6` → PR в `main`.

Схемы из `.puml` собирает [GitHub Actions](.github/workflows/plantuml.yml) в SVG и коммитит обратно в ветку при push. C4/sequence кладём в `TaskN/c4/*.puml`.

Опционально Task 3.1 (OpenTelemetry + Jaeger в k8s): конфиги от Практикума — [architecture-alexandrite-k8s-trace](https://github.com/Yandex-Practicum/architecture-alexandrite-k8s-trace).
